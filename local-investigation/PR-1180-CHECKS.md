## 仍要如实说明

- 安全报告还有两条 LOW 建议。第一条指出错误弹窗设置影响 WTA 及其子进程，
  范围判断是对的；这是防止后台进程被系统弹窗卡住的取舍，**不是关闭企业策略
  或吞掉错误**，退出码、日志和原生错误仍保留。第二条担心自动重连重置次数：
  查代码后，普通连接不带这个标记，只有明确重试或完成登录后才带，且用后清除。
  同一用户主动调用内部重试接口属于现有信任范围，不是发现了新的越权漏洞。
- “Skipped” 不一定有问题：前一步失败后不发布报告/修复，或者当前事件不是
  那个任务负责的事件，都应跳过。
- 合并 main 的本机验证另发现一个**与 main 完全相同**的 Rich Tab 测试失败：
  PowerShell 对带方括号的假 Git 路径处理不一致。它与 ACP 消息改动无差异，
  没有删除断言或假装通过，需要单独跟踪。
- 人工审批是另一项正常要求：仍需要一位非作者审查并批准，我不能替他批准。
- 本次不为了绿灯修改程序来迎合缺证据的报告，也不放宽检查标准。无障碍报告应补齐
  文件引用；性能工具应保证超时前留下报告并正确提供检测工具。剩余红灯继续如实保留。
